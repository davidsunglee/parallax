# Architecture decisions

These records explain decisions and their alternatives at the time they were
made. The current behavioral contract lives in the owning core specification;
Python-specific public choices live in the Python binding documents.

An accepted ADR is historical evidence, not a second specification to keep
synchronized. For a consequential reversal, add a superseding decision and link
the earlier record. Correct factual mistakes when useful, but do not rewrite
the old rationale to describe a later implementation. Routine refactors need
no ADR. Keep new records focused on the choice and tradeoffs, with links to the
contract rather than a copy of its rules.
